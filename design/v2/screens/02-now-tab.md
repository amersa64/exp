# 02 — Now tab

The prescription, when you ask to see it. Replaces v1's Train tab. Same job, demoted from default landing to "the place you go after the coach said 'show me the session'."

## Role

This is the EXECUTE surface (spec §4.1). When the user is ready to train, they come here to see exactly what to do. Now is **detail**; Coach is **direction**. Two distinct jobs, two tabs.

The mental model shift: in v1, Train was the front door — implying *"the workout is the product."* In v2, Now is the *spec sheet* — *"the relationship is the product, the workout is a deliverable of it."*

## What changed from v1's Train tab

| Element | v1 | v2 |
|---|---|---|
| Toolbar streak | "●23 · 3d" | **`●27` only.** Just votes. No streak. |
| Title | "Train" | **"Now"** |
| The Script copy | "After my morning coffee, I will start Full B at the garage." | **"After your morning coffee, you train Full A. In the garage."** — second-person, declarative, no "I will" |
| "Schedule on calendar" CTA | Always visible | **Hidden** until F2 Google Calendar OAuth ships |
| Three CTAs (Log / Schedule / Min dose) | Stacked vertically | **One CTA** (Log) + conditional minimum-dose card |
| Minimum-dose card | Always visible | **Conditional surfacing** (see below) |
| Per-exercise volume display | "3×5" in big gold | Preserved — but **add delta indicator** ("+5 from last" / "holding") |
| Progression rule | Single line at bottom in muted text | Preserved with "↗" prefix; same place |
| Ripples banner (after logging) | Inline above content | Preserved, but **coach voice from the response is rendered prominently above ripples** (see `06-log-session-v2.md`) |

## Minimum-dose card — when it appears

The Bad-day card was always visible in v1. Permission-to-half-ass at all times is permission unused. In v2, it's conditional:

| Condition | Show card? |
|---|---|
| Default (anytime before 6pm with no log) | No |
| After 6pm local with no log | **Yes** — last-chance affordance |
| Calendar shows >4 scheduled events today | **Yes** — heavy day |
| User reported "skipped" in last 2 days | **Yes** — slip recovery support |
| User is currently in a Shape-C slip-day state | Coach tab handles it; Now tab still shows it for redundancy |

The dose text itself is generated by the voice pipeline against the prescribed session. The phrasing is calibrated to be specific: not "do something easy" but "one set of squats at 95 — two minutes." Specific minimum > vague minimum.

```
│   Tomorrow is Full B —      │
│   coffee, garage.           │
│                             │
│   ┌─────────────────────┐   │
│   │ See tomorrow's      │   │
│   │ session             │   │
│   └─────────────────────┘   │
│                             │
└─────────────────────────────┘
```

A user who navigates to Now on a rest day sees this. The "see tomorrow's session" peek shows the upcoming Full B without logging — read-only preview.

> This is a subtle but important behavioral cue: we **don't** show today's empty session shell with "rest" written across it. That would frame rest as the absence of work. Instead we lead with "off today" — rest is the thing today *is*, not the thing today *isn't*.

## Per-exercise row — delta indicator

The new "+5 from last" / "holding" subline below the volume:

```
│ ┌─────────────────────────┐ │
│ │ 1  Squat           3×5  │ │
│ │       150 lb · 180s     │ │
│ │       +5 from last      │ │  ← new in v2
│ └─────────────────────────┘ │
```

Possible deltas:
- `+5 from last` (ember)
- `+10 from last` (ember, brighter)
- `holding` (muted)
- `−5 deload` (amber)
- `new exercise` (gold, on first appearance)

This single line answers the question every user asks looking at their session: *"is this the same as before, or did something change, and what?"* Today they have to remember; in v2, the prescription answers itself.

## Why this tab still exists

A skeptic could argue: if the Coach tab tells you what to do, why do you need the Now tab at all? Two reasons:

1. **Density.** The exercise list, loads, rest times, and progression rule don't fit comfortably in a coach card. They need their own surface.
2. **Mode separation.** When the user is *in* the gym, they want to stop hearing from the coach and start seeing the numbers. The Coach tab is for "what should I do." The Now tab is for "what are the numbers." Different mental modes.

The Now tab is the **reference manual**. The Coach tab is the **conversation**. Both have to exist.

## Open questions

- Should the per-exercise row be tappable for a video / form cue? Possibly — but probably not in v1. We've decided Marcus doesn't post on Instagram; the brand contract is that we *don't* dump videos at the user. If the user needs form coaching, they need a human. That's the spec §4.4 hand-off.
- Should there be a rest-timer button in each row? Real coaches don't manage rest for clients — the lifter manages their own clock. But many tracker apps do this. Probably keep out of v1. If it's a feature users ask for repeatedly, add later.
- Where does the *previous* session's actual log go? Currently nowhere in the iOS app surfaces it. Probably belongs as a small section at the bottom of the Now tab: "Last session: Tuesday — all sets clean at 145." Useful, doesn't take much space. Add to v2.
